# 设备分组功能方案

## 一、需求分析

管理 40+ 台设备时，需要按物理位置或用途进行分组管理：
- 按区域：一楼大厅、二楼走廊、会议室...
- 按用途：广告屏、导视屏、信息屏...
- 支持批量操作：选中分组 → 一键下发排程

## 二、数据库设计（向后兼容方案）

### 2.1 新增 DeviceGroupModel 表

```python
class DeviceGroupModel(Base):
    __tablename__ = "device_groups"
    
    id = Column(Integer, primary_key=True, autoincrement=True)
    name = Column(String(100), nullable=False, unique=True)  # 分组名称
    description = Column(String(255), default="")            # 分组描述
    sort_order = Column(Integer, default=0)                  # 排序权重
    created_at = Column(DateTime, default=datetime.now)
```

### 2.2 修改 DisplayModel（保留 group_name 兼容）

```python
class DisplayModel(Base):
    # ... 现有字段 ...
    group_name = Column(String(100), default="default")  # 保留：向后兼容 Player 端
    group_id = Column(Integer, ForeignKey("device_groups.id"), nullable=True)  # 新增：关联分组表
```

**关键设计**：
- 保留 `group_name` 字段，Player 端注册时仍可使用
- 新增 `group_id` 外键，前端优先使用 `group_id` 关联分组
- API 返回时同时返回 `group_name`（兼容旧 Player）和 `group_id`

### 2.3 数据迁移（安全幂等）

```sql
-- 1. 创建新表（如果不存在）
CREATE TABLE IF NOT EXISTS device_groups (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(100) NOT NULL UNIQUE,
    description VARCHAR(255) DEFAULT '',
    sort_order INTEGER DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 2. 为 displays 表添加 group_id 字段（如果不存在）
ALTER TABLE displays ADD COLUMN group_id INTEGER;

-- 3. 根据现有 group_name 自动创建分组并关联
INSERT OR IGNORE INTO device_groups (name) 
SELECT DISTINCT group_name FROM displays WHERE group_name IS NOT NULL AND group_name != 'default';

UPDATE displays SET group_id = (
    SELECT id FROM device_groups WHERE device_groups.name = displays.group_name
) WHERE group_id IS NULL AND group_name IS NOT NULL;
```

### 2.4 向后兼容保证

| 场景 | 兼容性 |
|------|--------|
| 旧 Player 发送 `group_name` | ✅ 保留字段，正常存储 |
| 新前端使用 `group_id` 筛选 | ✅ 优先查询 `group_id` |
| API 返回数据 | ✅ 同时返回 `group_name` 和 `group_id` |
| 排程绑定设备 | ✅ 使用 `display_ids` 列表，不涉及分组 |
| 现有排程数据 | ✅ 完全不受影响 |

### 3.4 设备更新 API 兼容

```python
# PUT /api/v1/displays/{id}
# 支持两种方式设置分组：
# 1. 旧方式：group_name: "一楼大厅"
# 2. 新方式：group_id: 1

# 处理逻辑：
if "group_id" in data and data.group_id:
    display.group_id = data.group_id
    # 自动同步 group_name（从分组表获取）
    group = db.query(DeviceGroupModel).get(data.group_id)
    if group:
        display.group_name = group.name
elif "group_name" in data:
    display.group_name = data.group_name
    # 自动同步 group_id（查找或创建分组）
    group = db.query(DeviceGroupModel).filter(DeviceGroupModel.name == data.group_name).first()
    if not group:
        group = DeviceGroupModel(name=data.group_name)
        db.add(group)
        db.flush()
    display.group_id = group.id
```

### 列表视图需求

**背景：** 40+ 台设备用卡片视图太占空间，一眼看不到几个。需要表格视图快速扫描和管理。

**功能设计：**
- 卡片/列表视图切换按钮（右上角）
- 表格列：勾选 | 名称 | 状态 | 平台 | IP | 分辨率 | 方向 | 分组 | 操作
- 表头可排序（点击列标题）
- 行内操作按钮（编辑/截屏/熄屏/唤醒/重启/删除）
- 行内分组下拉快速移动
- 复选框支持全选/批量操作
- 保持与卡片视图相同的数据和筛选逻辑

**适用场景：**
- 设备数量多（10+）时切换到列表视图
- 需要快速对比设备信息（IP、平台、分组）
- 批量操作时更直观

## 七、影响分析（确保无 BUG）

### 7.1 不受影响的功能

| 功能 | 原因 |
|------|------|
| 排程绑定设备 | 使用 `display_ids` 列表，不涉及分组字段 |
| 播放器心跳 | 只更新 `last_heartbeat` 和 `status`，不涉及分组 |
| 播放器同步 | 根据 `display_id` 获取排程，不涉及分组筛选 |
| 素材管理 | 完全独立，不涉及设备分组 |
| 布局设计 | 完全独立，不涉及设备分组 |
| 截图功能 | 只读取设备信息，不修改分组 |

### 7.2 需要兼容的场景

| 场景 | 兼容方案 |
|------|----------|
| 旧 Player 注册时发送 `group_name` | 保留字段，正常存储 |
| 新 Player 可选发送 `group_id` | 支持新字段，自动同步 |
| 前端使用 `group_id` 筛选 | 优先查询 `group_id` |
| 未分组设备 | `group_id = NULL`，归入"未分组"标签 |

### 7.3 数据迁移风险

| 风险 | 缓解措施 |
|------|----------|
| 迁移脚本执行失败 | 使用 `ALTER TABLE ADD COLUMN IF NOT EXISTS` 幂等语句 |
| 分组表创建失败 | 使用 `CREATE TABLE IF NOT EXISTS` |
| 数据不一致 | 迁移后自动同步 `group_name` ↔ `group_id` |
| 迁移过程中服务中断 | 迁移脚本在 `init_db()` 中执行，启动时自动完成 |
