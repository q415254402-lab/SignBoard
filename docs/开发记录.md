## 时间线

### 2026-06-03 — 需求调研与架构设计

**调研阶段**
- 评估了现有开源方案（Xibo 等），确认其 PHP + C# 架构不符合团队需求
- Xibo 分析：PHP CMS + C# Player，XMDS 协议，功能完善但技术栈不匹配
- 决策：自建 Python 全栈方案

**技术决策**
- 确认 Server/Player 分体架构，各打包为独立 EXE
- Server: FastAPI + SQLAlchemy + SQLite + PyQt6 状态窗口
- Player: PyQt6 + Qt Multimedia，全屏无边框
- 同步方式：30秒 HTTP 轮询（替代 WebSocket，更简单可靠）
- 前端：HTML + Tailwind CSS CDN，零构建
- 布局模板：全屏轮播 / 播放列表 / 左右二分屏（1:1/16:9）/ 上中下三分屏
- 音频：视频独立音轨 + 独立 BGM，音量分开控制
- PPT：上传自动转图片序列（LibreOffice 优先，python-pptx fallback）
- 截图：60秒自动 + CMS 手动触发
- 远程控制：CMS 可下发重启指令

**需求确认**
- 20 台 Windows 屏幕，纯内网
- 单 EXE <500MB
- 过渡动画：淡入淡出
- 走马灯：可配颜色/字体/速度
- Web 管理界面 "slightly nice"

### 2026-06-04 下午 — 打包修复

**问题 1：`signboard-server.exe` 在 Windows Server 上弹出 `ImportError: DLL load failed while importing QtWidgets`**
- 根本原因：`status_window.py` 在模块顶层 `import PyQt6`，而 `main.py` 里 `from server.status_window import get_local_ip` 即使在 `--no-gui` 模式下也会触发该 import，导致 Python 在 import QtWidgets 时加载 Windows 系统 DLL（d3d11.dll/dxgi.dll 等），Windows Server 缺少桌面体验组件故失败
- 表象：双击 exe 立即弹错误窗口闪退，`--no-gui` 模式同样崩溃

**修复过程（多轮迭代）：**

| 轮次 | 尝试 | 结果 |
|---|---|---|
| 第 1 轮 | `main.py` 里用 `os.environ["PATH"]` + `QT_PLUGIN_PATH` 设置 DLL 搜索路径 | 无效，Python import 时机晚于预期 |
| 第 2 轮 | 新增 `runtime_hook.py`，用 `os.add_dll_directory()` 在 PyInstaller bootloader 阶段设置 DLL 路径 | 本地测试通过，但 Windows Server 仍失败（缺的是系统级 DirectX DLL，不是我们的 Qt DLL） |
| 第 3 轮 | **把 `get_local_ip()` 内联到 `main.py`**，彻底切断 `status_window.py` 的顶层 import；同时在 `if not args.no_gui:` 块内加 `try/except ImportError` 自动降级 | ✅ 最终方案 |

**最终修复：**
1. `get_local_ip()` 移到 `server/main.py` 内联（不依赖 `status_window.py`）
2. GUI 启动包裹在 `try/except ImportError` 中，Qt 加载失败时自动降级为控制台模式并打印提示
3. 保留 `runtime_hook.py` 用 `os.add_dll_directory()` 设置 DLL 搜索路径（对有桌面环境的机器有效）
4. Player 的 `--server` 改为可选参数，不带参时弹出 Qt 配置对话框
5. Player 也加 Qt import 失败时的友好错误提示

**问题 2：Player 双击闪退**
- 原因：`argparse` 中 `--server` 设为 `required=True`，不带参数即报错退出
- 修复：`--server` 改为 `default=None`，无参时弹出 `SetupDialog` 配置窗口，输入自动保存到 `player_config.json`

**问题 3：Web 管理后台创建排程时弹出 `[object Object]`**
- 原因：FastAPI 422 验证错误返回的 `detail` 是数组 `[{loc, msg, type}]`，前端 `throw new Error(err.detail)` 把数组转成字符串 `[object Object]`
- 修复：`admin/index.html` 里 `api()` 函数的错误处理改为先 `Array.isArray()` 判断，再 `msg.map(e => e.msg + ' (' + e.loc.join('.') + ')').join('; ')` 拼接

**问题 4：Web 管理后台点击无反应（2026-06-04 13:35 发现，14:50 修复）**
- 现象：点素材/布局/排程等所有按钮都没反应，浏览器控制台报 JavaScript 错误
- 根因：`api()` 函数缺少闭合 `}`，导致 `toast()` / `formatTime()` / `formatSize()` 等全局函数被定义在 `api()` 内部，全局不可访问
- 修复：`admin/index.html` 第 151 行后补上 `}`
- 验证：修复后所有页面按钮正常响应，toast 弹窗正常

## 已解决的关键问题

1. **PPT 转换**：两级 fallback 策略（LibreOffice → python-pptx），保证任何环境下都能工作
2. **视频播放**：Qt Multimedia 原生支持，无需额外解码器
3. **全屏隐藏鼠标**：`BlankCursor` + `FramelessWindowHint` + `StaysOnTopHint`
4. **过渡动画**：QGraphicsOpacityEffect + QPropertyAnimation 属性动画
5. **PyInstaller 打包**：`.spec` 文件 + `--onedir` 模式，显式收集所有 Qt6 DLL/plugins + VC++ 运行时
6. **SQLite 并发**：SQLAlchemy Session 每次请求独立创建，无锁冲突
7. **Windows Server 兼容**：内嵌 VC++ 运行时 DLL，`--no-gui` 模式完全避开 Qt，纯控制台即可运行
8. **Qt 加载失败自动降级**：Server 在无桌面环境自动切换控制台模式，不会闪退
9. **Player 配置对话框**：首次启动无命令行参数时弹出 GUI 输入服务器地址，配置持久化保存

> 代码审查后在实际部署环境中测试，发现并修复了一系列运行时问题。

**问题 9：Player 打包后图片显示为缩略图大小**
- 现象：1920×1080 屏幕上图片只有一小块，四周大黑边
- 根因：`ImageRenderer.set_image()` 在 widget 未布局时调用 `self.size()`，返回默认小尺寸（约 640×480），全屏后不重新缩放

**现象：** 服务器断开后 Player 不会自动切换到缓存播放；服务器恢复后不会自动切回在线

- 设计（功能 1）：「同步失败 → 读 last_sync.json + media/ 缓存播放 → 后台重试 → 服务器恢复后自动切回在线」

- `player/sync.py`：

  - 新增 `_try_offline_fallback()` 方法：加载 `last_sync.json` 缓存 → 检查素材文件本地存在性 → emit 缓存数据
  - `_do_sync()` 所有异常分支（ConnectError / TimeoutException / 通用异常）调用 `_try_offline_fallback()`
  - 连接成功后重置 `_offline_mode = False`
  - 防重复：已在离线模式时不再重复 emit 缓存数据
- `player/player_window.py`：
  - `_on_connection_changed()` 已播放状态下显示角落「⚠ 离线模式」红色标签（不影响播放），不再显示全屏 loading

#### 问题 22：离线重启后不播放素材

**现象：** 服务器离线，重启播放器，窗口打开但不播放素材（黑屏）

**根因追踪：**
```
main.py → 注册失败 → display_info.json 恢复 display_id → PlayerWindow
→ _setup_sync() → first_sync() → _do_sync() → ConnectError
→ _try_offline_fallback()
→ load_cached_sync() 读到缓存 ✅
→ has_media=True ✅
→ emit schedule_updated ✅
→ _on_schedule_updated() → get_media_path(media_id)
→ 查 _cached_media[media_id] → 空字典 {} → 返回 None！
→ media_paths = {}（空）
→ _switch_layout(layout, {}) → 布局无素材 → 黑屏
```

**根因：** `_cached_media` 字典只在 `_do_sync()` 成功路径（连接服务器成功 → 遍历 media_list → 写入）中填充。`_try_offline_fallback()` 虽然加载了缓存数据并 emit，但没有把缓存中的 media_list 填入 `_cached_media`，导致 `get_media_path()` 永远返回 None。

**前两次修复为什么没解决：**
- 第 1 次（v1.1.1）：加了 `_try_offline_fallback()` 方法，能 emit 缓存数据了，但没填充 `_cached_media`
- 第 2 次（v1.1.1）：加了 `_offline_mode` 标记防重复 emit，仍然没解决 `_cached_media` 为空

**修复（第 3 次）：** `player/sync.py` — `_try_offline_fallback()` 内遍历 media_list 同时填充 `_cached_media`：
```python
for m in media_list:
    local_path = os.path.join(self.media_cache_dir, m["file_path"])
    if os.path.exists(local_path):
        has_media = True
    self._cached_media[m["id"]] = m  # ← 关键修复
```

#### 问题 23：服务器恢复后永远黑屏

**现象：** 服务器恢复后，播放器不刷新，永远黑屏

**根因追踪：**
```
服务器恢复 → _do_sync() 成功 → 下载素材 → emit schedule_updated
→ _on_schedule_updated():
    layout_key = f"{layout['id']}_{layout.get('created_at', '')}"
    if layout_key == self._current_layout_key:  # ← 布局没变
        return  # ← 直接 return，_switch_layout 永远不被调用！
```

**根因：** 布局 key 变更检测只比较 layout_id + created_at。如果排程/布局没变（服务器恢复后同一个排程），`layout_key` 相同 → return。但离线阶段创建的布局 widget 可能是用空 `media_paths` 创建的（素材文件不存在），恢复后虽然素材下载成功了，但布局不会重建。

**修复：** `player/sync.py` — `_do_sync` 成功后，如果之前处于离线模式，给 data 加 `_force_refresh=True` 标记。`player/player_window.py` — `_on_schedule_updated` 检查 `_force_refresh`，为 True 时跳过 `layout_key` 变更检测。
```python
# sync.py
was_offline = self._offline_mode
if was_offline:
    data["_force_refresh"] = True

# player_window.py
force_refresh = data.get("_force_refresh", False)
if layout_key == self._current_layout_key and not force_refresh:
    return
```

#### 问题 24：下载失败的素材不会重试

**现象：** 素材下载失败后，后续同步不会重试下载

**根因：** `_do_sync()` 的下载判断是 `if media["id"] not in self._cached_media`。下载失败后 `_cached_media` 已被填充（metadata），但文件不在磁盘上。后续同步看到 ID 已在字典中，跳过下载。

**修复：** 改为检查文件是否在磁盘上：
```python
# 之前
if media["id"] not in self._cached_media:
    self._download_media(media)

# 现在
local_path = os.path.join(self.media_cache_dir, media["file_path"])
if not os.path.exists(local_path):
    self._download_media(media)
```

#### 问题 27：`_force_refresh` 污染缓存文件

**现象：** `_save_sync_cache(data)` 把 `_force_refresh=True` 存入 `last_sync.json`。播放器重启时加载缓存，这个标记导致不必要的强制刷新。

**问题：** `verify_password` 使用 `==` 比较字节串，短路求值导致比较时间随匹配前缀变化，存在时序侧信道风险。
