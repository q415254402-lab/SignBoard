# 开关机计划 + 下发记录 — 开发方案

> 日期：2026-06-15

---

## 一、需求确认

- "关机" = 熄屏（screen_off）
- "开机" = 唤醒（screen_on）
- 时间段计划由用户配置，什么时候开、什么时候关
- 独立页面管理，绑定对应屏幕
- 下发记录：查看布局/命令下发的记录，成功/失败状态

## 二、数据库设计

### 2.1 新建 PowerScheduleModel（开关机计划表）

```python
class PowerScheduleModel(Base):
    __tablename__ = "power_schedules"

    id = Column(Integer, primary_key=True)
    name = Column(String(255))                             # 计划名称 "工作日开关机"
    display_ids = Column(Text, default="[]")               # JSON: 绑定的屏幕 ID 列表，空=全部
    on_time = Column(String(5))                            # 开机时间 "08:00"，null=不控制开机
    off_time = Column(String(5))                           # 关机时间 "22:00"，null=不控制关机
    power_days = Column(String(50), default="1,2,3,4,5")   # 执行日 "1,2,3,4,5"，周日=0
    is_enabled = Column(Boolean, default=True)             # 是否启用
    created_at = Column(DateTime, default=datetime.now)
```

### 2.2 新建 CommandLogModel（下发记录表）

```python
class CommandLogModel(Base):
    __tablename__ = "command_logs"

    id = Column(Integer, primary_key=True)
    display_id = Column(Integer, ForeignKey("displays.id"))
    display_name = Column(String(255))     # 冗余，方便查询
    command = Column(String(50))           # screen_off/screen_on/restart/layout_sync/screenshot
    detail = Column(Text)                  # JSON: 补充信息（如布局名）
    status = Column(String(20))            # success/failed
    error_msg = Column(Text, nullable=True)
    triggered_by = Column(String(20))      # schedule/manual
    created_at = Column(DateTime, default=datetime.now)
```

### 2.3 数据迁移

```sql
-- 开关机计划表
CREATE TABLE IF NOT EXISTS power_schedules (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(255),
    display_ids TEXT DEFAULT '[]',
    on_time VARCHAR(5),
    off_time VARCHAR(5),
    power_days VARCHAR(50) DEFAULT '1,2,3,4,5',
    is_enabled BOOLEAN DEFAULT 1,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 下发记录表
CREATE TABLE IF NOT EXISTS command_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    display_id INTEGER,
    display_name VARCHAR(255),
    command VARCHAR(50),
    detail TEXT,
    status VARCHAR(20),
    error_msg TEXT,
    triggered_by VARCHAR(20),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

## 三、API 设计

### 3.1 开关机计划 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/power-schedules` | 获取所有开关机计划 |
| POST | `/api/v1/power-schedules` | 创建计划 |
| PUT | `/api/v1/power-schedules/{id}` | 更新计划 |
| DELETE | `/api/v1/power-schedules/{id}` | 删除计划 |
| PATCH | `/api/v1/power-schedules/{id}` | 启用/禁用 |

### 3.2 下发记录 API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/command-logs` | 查询下发记录（筛选：设备/命令/时间） |

参数：
- `display_id`: 按设备筛选
- `command`: 按命令类型筛选
- `triggered_by`: 按触发方式筛选（schedule/manual）
- `start_time` / `end_time`: 时间范围
- `page` / `page_size`: 分页

## 四、后台调度逻辑

每 60 秒执行 `_check_power_schedules()`：

1. 查询所有 `is_enabled=True` 的开关机计划
2. 对每个计划，解析 `display_ids` 获取目标设备
3. 对每台设备：
   - 获取当前时间 `HH:MM` 和星期几 `weekday`（0=周日）
   - 检查 `weekday` 是否在 `power_days` 内
   - 如果当前时间 == `on_time` → 下发 `screen_on` 命令
   - 如果当前时间 == `off_time` → 下发 `screen_off` 命令
4. 防重复：记录当天已执行的 `(plan_id, display_id, time_slot)`，避免同一时间重复下发
5. 每次执行写入 `command_logs`（`triggered_by="schedule"`）

## 七、网页组件播放问题（待讨论）

### 7.1 现状

| 平台 | 支持情况 | 说明 |
|------|----------|------|
| Windows | ❌ 不可用 | `WebpageRenderer` 代码存在，但依赖 `PyQt6-WebEngine` 未安装 |
| Android | ❌ 未实现 | 无任何 WebView 相关代码 |

### 7.2 问题分析

**Windows**：
- `player/renderer.py:250` 尝试 `from PyQt6.QtWebEngineWidgets import QWebEngineView`
- `requirements-player.txt` 无 `PyQt6-WebEngine`，import 失败降级为文字标签
- 即使加上依赖，`PyQt6-WebEngine` 约 100MB+，打包体积翻倍

**Android**：
- 前端布局编辑器支持创建 `webpage` 类型布局
- Player 端无任何处理，收到 webpage 布局不显示内容

### 7.3 方案选项

#### 方案 A：双端加 WebView 依赖

| 平台 | 实现 | 打包体积影响 |
|------|------|-------------|
| Windows | `PyQt6-WebEngine` | +100~200MB |
| Android | 系统 `android.webkit.WebView` | 几乎无影响 |

**优点**：完整网页渲染能力
**缺点**：Windows 打包体积大增，PyQt6-WebEngine 稳定性一般

#### 方案 B：iframe 嵌入截图（轻量方案）

网页组件改为：Server 端定时截图网页 → 下发图片给 Player 播放

**优点**：无额外依赖，打包体积不变
**缺点**：非实时（每 N 秒刷新一次截图），无法交互

#### 方案 C：仅 Android 实现，Windows 用 iframe 图片

| 平台 | 实现 |
|------|------|
| Windows | Server 截图下发图片（无依赖） |
| Android | `android.webkit.WebView`（系统自带） |

**优点**：Android 实时渲染，Windows 无额外依赖
**缺点**：两端体验不一致

### 7.4 待确认

1. 是否需要网页组件实时渲染（可交互）还是展示即可？
2. Windows 端能否接受打包体积增加 100~200MB？
3. 网页组件的使用频率高吗？是否值得投入？
